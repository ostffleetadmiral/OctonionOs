# Octonion-OS Lattice Engine

Standalone Zig 0.13.0 project for an integer-first 15³ signed-coordinate lattice, a translated Fano label tensor, a quantized Quad-Smith table, sparse scaling metadata, and deterministic JSON export. Agent rules and project law live in `AGENTS.md`.

## Verification

```sh
zig build test
zig build test-core
zig build test-sidecar
```

The core uses integer data only. `sidecar/quad_smith.zig` performs f64 Shirley square-to-disk mapping and normalized impedance conversion, then quantizes the 225 central-slice entries at scale `1_000_000_000`.

## Sparse scaling tiers

The core lattice remains 15³ (3,375 nodes). In each axis, its signed local coordinate `[-7,+7]` is translated into core indices `[0,14]`; the 16³ container adds exactly one coordinate plane, either index `15` for positive padding or index `0` for negative padding. The signed True-Origin is preserved at index `7` or `8` per axis. The wrapper records `16³ - 15³ = 721` added cells without allocating a dense 4,096-cell volume. The three selected outer faces contain 3×16² cells, with their intersections shared; they are not the 721-cell volume difference. The remaining wrapper boundary is represented sparsely. “Insulation,” “communication,” and “quantum foam” are descriptive model terms only.

| qbits | dimensions | universes | base side | padded side |
|---:|---:|---:|---:|---:|
| 1 | 8 | 1 | 15 | 16 |
| 2 | 16 | 8 | 30 | 32 |
| 4 | 32 | 64 | 60 | 64 |
| 8 | 64 | 512 | 120 | 128 |

The qbit, dimension, and universe values are supplied symbolic metadata; the code checks exact 15-wide base-side multiples and power-of-two padding arithmetic only. The 30/60/120 base spans are not 16-stride tilings. Seam contacts do not derive entanglement or physical state transfer. Placement records are caller-supplied integer container origins in the global `[0,padded_side-1]³` frame, with independent per-axis padding direction. Full container bounds must not overlap. Face-adjacent and shared-cell contacts are represented distinctly; face side references and complementary shell direction are checked only on the contact axis, leaving tangential orientations independent. No canonical placement layout is assumed.

## Secondary E0 routing

There are exactly 420 eligible non-origin `e0` label sites; the geometric primary origin is immutable and excluded. The router keeps stable token IDs, occupied-slot reservations, and transient source/destination locks. A candidate must be a one-step axis transition between eligible sites. The tensor supplies node labels but no separate edge graph; the current tensor has zero axis-adjacent eligible `e0` pairs, so the router reports unsupported paths instead of inventing connectivity. Batch contenders for a destination are compared by Manhattan distance, lexicographic source `(x,y,z)`, then token ID. Valid competing requests report `.arbitration_lost`; invalid moves are reported separately and leave state unchanged. Reservations persist until a successful move; source/destination locks exist only during a committed transition. Core logic is integer-only; no impedance-derived collision behavior is implemented.

The JSON writer and SHA-256 manifest helper are in `src/serialize.zig`; serialization covers tier metadata, sparse shell data, caller placements/seams, tokens, and reservations. The lattice, Fano labels, Smith mapping, and tier registry are computational constructions; passing tests does not prove physical or quantum interpretations.

## Isolated quantum-behavior software probes

`src/quantum_model.zig`, `src/interference.zig`, and `src/observer.zig` form an isolated integer fixed-point validation lane. It tests a bounded two-qubit state-vector model with checked Q32.32 arithmetic, explicit rounding, pure sampling plus an explicit collapse operation, deterministic seeded software-shot batches, all eight local phase rotations in a two-path complex-amplitude model, and immutable observer snapshots. Gate updates are transactional, invalid state padding and arithmetic overflow are rejected, and seeded shot counts are bounded to `u32`. Phase maps to explicit complex unit-circle contributions and has two-path known answers across all eight labels; it is not a bare phase label or a reused transit counter. The lane remains separate from the 15³ lattice and its modulo-8 transit-phase options. Seeded simulation is deterministic and is not physical randomness; concurrence and Bell-state amplitudes are software outputs. The user interprets this software lane under the cyber-physical qbit premise, but it is not yet an experiment on the 15³ qbit's physical state. BLUE's separate RF/acoustic/CSI records do provide physical observations in their own channels; see `PHASE-QUANTUM-AUDIT.md` for the evidence mapping and the still-open connection to the lattice state and `i` measurement.

Run `zig run src/quantum_behavior_probe.zig` for a deterministic Bell, product-state, interference-fringe, and passive-observer software demonstration. Its seed-42 counts reproduce exactly; they are simulator outputs, not physical randomness or lab results. Detailed outputs and interpretation boundaries are recorded in `PHASE-QUANTUM-AUDIT.md`.

## Q#-style operation adapter

`src/qsharp_adapter.zig` maps a deliberately small Q#-style operation vocabulary (`H`, `X`, `Z`, `S`, `CNOT`, sample, measure-and-reset, reset) onto the existing bounded state-vector module. It is an API/semantics adapter, not a Q# runtime, a Bloch-sphere implementation, or the Octonion-OS 3D qbit engine. In particular, Q#'s conventional state vector has two complex amplitudes for one qubit; the Octonion-OS proposal is a lattice-backed 3D qbit and needs its own defined state, transition, measurement, and scaling contracts. The existing lattice stores the E0-aligned canonical labels and phase metadata, not those state-transition rules. This adapter leaves lattice labels and both transit-phase conventions unchanged.

`src/reversible_probe.zig` implements a separate classical reversible-computing lane, based on the inspected BLUE/Spec-007 and RedOx patterns: fixed-width register permutations, NOT/CNOT/Toffoli/Fredkin/SWAP/Peres gates, reverse-order algebraic uncompute, exhaustive 8-bit bijection tests, and a compute-copy-uncompute witness. Lattice-dynamics results are candidate-scoped: the directed `+1 mod 8` rule grows origin norm-square from 1 to 4, and a separate side-2 rounded stencil has an explicit collision; the rounded polynomial's origin/all-basis tests preserve measured norms but do not establish global injectivity. Exact-rational origin control and bounded Chebyshev evolution are separate candidates. A general lattice inverse remains open.

The inspected project-family Q# artifacts include verified simulator-lane H/CNOT correlations, CHSH outcomes, Grover outcomes, and a single-qubit unread-measurement/dephasing channel comparison. Their records scope those outcomes to the simulator and retain separate physical-QPU/device lanes. The Octonion-OS adapter does not import or revalidate those claims; its tests establish only its local API mapping. See `PHASE-QUANTUM-AUDIT.md` for the source comparison and evidence ledger.

Statuses distinguish verified executable behavior, corrected results, model metadata, REGISTER doctrine, unresolved/unresolvable questions, unsupported claims, and contradictions. `UNSUPPORTED` means no supporting artifact for that exact claim; it does not establish its negation. `CONTRADICTED` is reserved for a claim that fails its stated internal verifier. ### Transit phase contract

Both candidates are implemented as modulo-8 integer eighth-turn increments:

| Convention | Increment | Residues after transits 1–8 |
|---|---:|---|
| `quarter_turn_per_transit` | 1 | 1, 2, 3, 4, 5, 6, 7, 0 |
| `three_quarter_turn_per_transit` | 3 | 3, 6, 1, 4, 7, 2, 5, 0 |

Each sequence returns to zero after eight transits. Contract v1 pins `three_quarter_turn_per_transit` as `lattice.CANONICAL_PHASE_CONVENTION` because the Module-2 source spec specifies 3π/4 per transit (exactly three eighth-turns); `quarter_turn_per_transit` remains as the minimal-generator variant. The +3 sequence is the element-wise ×3 mod 8 image of +1, and ×3 is not an octonion automorphism, so label-coupled consumers can distinguish them. Callers must still select a convention for serialization; `null` is rejected. The manifest records the chosen ID, increment, and cycle length. Layer pivot metadata is not transit phase.

### Manifest contract

The `octonion-os-wall-v2` manifest is a deterministic software artifact, not a physical validation result or hardware gate. It is generated only for validated state and an explicitly chosen phase. Its JSON is syntactically parsed in tests; string values are escaped; invalid router state and over-capacity placement inputs are rejected. Placements, seams, tokens, and graph edges are canonically sorted. The SHA-256 digest binds the declared lattice labels, Smith entries, phase selection, scaling/shell metadata, placements, seams, routing policy/tokens/occupancy/edges, frame digests, and claim/provenance/source text. It is an integrity checksum for this declared model state, not proof that the claims are physically true.

Routing retains conservative one-step axial mode (which has no eligible e0-to-e0 edges in this tensor) and supports a caller-supplied canonical undirected graph over eligible sites. The graph is explicit serialized input, not inferred from labels. BLUE's defect-line rule has a reproduced coordinate example but is not adopted for secondary-e0 movement because some candidate steps leave the eligible set.

The pairing is model metadata, not a verified physical law: 256 and 512 saturate at the top rung.

`src/scaled_lattice_probe.zig` computes exact state histograms for inner sides through 480 without materializing volumes, using the O(n) triple-convolution of the one-axis mod-8 residue histogram (cross-checked against brute force on small sides). ## 3D lattice-native qbit

`src/lattice_qbit.zig` implements the current computational substrate for the project's **cyber-physical qbit**: one 3D qbit whose 3,375-cell basis is the 15³ interior, bounded by the 721-site 16³ shell, with Fano labels e0..e7 (421 e0 observer sites). This is distinct from a conventional microscopic quantum bit; under the framework premise that the universe is inherently quantum, the lattice qbit is a macroscopic, cyber-physical analogue. The module supplies a Q128 tight-binding Hamiltonian, Chebyshev evolution, basis/uniform-interior preparation, and population accounting. `src/lattice_measure.zig` adds measurement/readout contract v1: deterministic u64-selector Born sampling over all 4,096 sites, interior e-label class sampling, site collapse to a basis state, Lüders projection onto a label class, and non-mutating population/digest readouts — declared software semantics, not apparatus observations. `src/ivector_readout.zig` adds i-vector binding contract v1: shot histograms classify into the eight e-label components plus an explicit shell channel, and label populations quantize to i512 — declared conventions for what the software state says about the i-vector, not a physical projection claim. `src/reversible_lattice.zig` adds a lattice-native reversible transition contract v1: an octonion-cell (2×2×2 = 8 sites) Margolus-style CA on u8 sites over the 16³ torus whose primitives are provably bijective, giving exact step inverses — a candidate reversible rule on a classical byte lane, distinct from the Q128 amplitude state. The framework interprets `i` in `0^0=i` as a superposition until measured; local state-vector tests implement software superposition and explicit collapse, but do not yet map measurement onto the full i-vector/lattice qbit. The open evidence question is what physical observations most directly characterize this qbit and its state/readout mapping.
